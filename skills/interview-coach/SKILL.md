# interview-coach（面试复盘教练）

`agent` 型技能，用多轮对话陪用户复盘面试，不是固定工作流，也不强行按步骤生成报告。

## 当前能力

- 指导用户从 FFmpeg 官方下载页进入 Windows 构建页，取得 64 位 release essentials 包。
- 给出视频提取音频的 Windows 命令，并区分“提取音频”和“语音转文字”。
- 支持上传面试音频，后台调用 Qwen-Audio-3.x ASR Filetrans，提供任务进度和带
  说话人编号/时间戳的转写文本。
- 支持建立多份面试档案；每份可追加多段音频，音频、转写任务和结果都固定归属到该档案，
  不会因切换对话或后续上传而串到另一场面试。
- 可把转写稿整理为待用户核对的 Q&A 草稿；单题复盘会保留版本历史，并可记录下一次面试前的练习行动项。
- ASR 复用「语音识别模型」槽位里的地址、模型名和密钥。
- 用户可直接粘贴文字稿，随后围绕问答、表达和思路逐题复盘。
- 记录用户的复盘目标与薄弱点，后续在同一会话中继续改进。

## 数据边界

- 当前不要求用户把原始视频上传到工作站；视频处理全部在用户本机完成，工作站只接音频。
- 音频会通过临时公网链接交给百炼，任务结束后链接撤销。
- 完整音频与 ASR 转写 JSON 保存在文件区；PG 仅保存面试、录音、任务和结果的关系与索引。

## 设计边界

- 复用现有 agent、LLM、会话和记忆能力，不另建工作流引擎。
- 复盘不是固定模板。用户可只学 FFmpeg、只讨论一道题，或继续完整复盘。
- Q&A 提取只保存文本中有证据的草稿，必须先让用户核对；不会把模型猜测当作面试原话。
- FFmpeg 只负责提取音频，不能把音频转成文字。
- ASR 适配器按协议拆分；当前的 DashScope Filetrans 实现只承诺 Qwen-Audio-3.x，
  别的服务商或不同响应结构需要单独适配。
